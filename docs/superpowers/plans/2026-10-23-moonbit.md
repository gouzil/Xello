# MoonBit Implementation Plan

**Goal:** Make `moonbit` a first-class optional caller and callee for every
available stable target: C, the new native code generator, JavaScript, Wasm
and Wasm GC.

**Architecture:** Keep one language identity and a shared MoonBit CLI/provider.
Select `c|native|js|wasm|wasm-gc` using `--moonbit-backend` or
`MOONBIT_BACKEND`; record the selection in the language manifest. Separate
build caches prevent incompatible generated artifacts from being reused.

- C release generation and new native debug object generation use native
  executables and C ABI shared providers with hidden MoonBit runtime symbols.
- VM runners execute real compiled MoonBit artifacts inside Node.js. A
  Node-API addon loads existing C ABI providers in the same process.
- VM providers use the existing Python/C API boundary with `mini-racer` V8.
  JS exports strings; Wasm targets export managed byte accessors. No matrix
  edge launches another runner process.
- Keep Python loaded while embedded runtime threads are alive. On Linux,
  expose Python symbols to its extensions and isolate MiniRacer's V8 symbols
  from Node's V8 symbols.

## Scope

- Register MoonBit in every runner, manifest, Make target and benchmark.
- Build the shared CLI and provider for all five backend selections.
- Extend Docker, compile/test/format CI, formatting hooks and bilingual docs.
- Reuse dynamic matrix tests for direct calls, all runner matrices, fanout,
  mixed chains, JSON, timing and Make command routing.
- Cover missing toolchains, selected artifacts, hidden runtime symbols, null
  and empty callers, invalid UTF-8, long Unicode input and repeated ABI calls.

## Review focus

- Missing MoonBit tools are reported by default; explicitly requesting an
  unavailable toolchain fails with an actionable error.
- Selecting a VM target requires Node.js 22+, Node-API headers and MiniRacer.
- Native runtime symbols must not interpose between runner and provider.
- Copy returned bytes before freeing MoonBit memory or closing a library.
- Respect the manifest and reject invalid CLI input before provider calls.
- Preserve process-local calls across every backend and every existing runner.

## Verification and limits

macOS arm64: all five backend selections passed the full 35-test suite, with
34 passes and the Linux-only Kotlin residency test skipped. After the Linux
runtime fixes, the JS and Wasm GC suites were repeated successfully.

Linux amd64 Docker, running under emulation on an arm64 host: all five
backend selections passed all 35 tests with nine languages available. This
covers 81 direct caller/callee pairs, every runner's matrix, fanout, mixed
chains, ABI edge cases and benchmark/Make routing for each backend.

The final Wasm GC Docker image passed its full nine-language source build,
mixed-chain smoke and 81-edge MoonBit matrix. A clean toolchain download
stalled on JetBrains DNS/TLS errors; the successful build reused the existing
Kotlin dependency cache from the earlier successful toolchain image. No
prebuilt application artifacts were substituted. Prek, Node syntax checks
and `git diff --check` passed for the final source changes.

Windows and the experimental LLVM target remain unsupported. The stable
MoonBit toolchain does not ship the LLVM standard library. The new native
generator uses debug mode; C uses release optimization, and VM timings
include Python/V8 bridge costs. Toolchain upgrades require revalidation.
